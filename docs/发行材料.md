## 固定输入

| 文件 | 用途 |
| --- | --- |
| `runtime/sources.lock.json` | 基础环境和原生资源来源 |
| `runtime/projects.lock.json` | AstrBot、NapCat、QQ 等运行组件版本 |
| `runtime/astrbot-python.lock.txt` | Python 安装依赖 |
| `runtime/distribution-sources.lock.json` | 上游源码归档来源与摘要 |
| `runtime/python-sources.lock.json` | Python 源码归档及原始来源信息 |
| `runtime/shizuku-api.lock.json` | Shizuku SDK 版本、Maven 坐标及许可来源与摘要 |
| `runtime/shizuku-manager.lock.json` | 官方 Shizuku 安装包身份、来源、大小、摘要及许可 |
| `runtime/deepseek-harness.lock.json` | 可选 Harness 与 Node.js 的固定版本、来源及完整性信息 |
| `runtime/desktop-packages.lock.json` | 完整 APK 桌面离线包、二进制与源码版本、来源及摘要，绑定基础镜像 |
| `app/src/main/assets/runtime/harness/package-lock.json` | Harness 按需安装的 npm 依赖锁与逐包完整性信息 |

收集工具读取固定镜像、实际 Gradle 发行依赖和源码白名单，不读取手机数据。版本、归档大小和 SHA-256 必须与锁文件一致。

## 收集

```powershell
./gradlew.bat :app:collectReleaseDependencyMetadata '-PbundledRuntime=true'
python -B -X utf8 tools/build_support/collect_distribution.py --apk-assets runtime/distribution-assets --desktop-materials-directory ../desktop-materials
python -B -X utf8 tools/build_support/verify_distribution.py --desktop-materials-directory ../desktop-materials
```

上游源码归档按锁文件放入 `.cache/distribution/sources/`，AstrBot 原始归档放入 `.cache/upstream/`。完整运行镜像位于 `runtime/apk-assets/bootstrap/arm64-v8a/`。

若输入与输出位于工程外，可显式指定目录：

```powershell
python -B -X utf8 tools/build_support/collect_distribution.py --runtime-dir ../build-inputs/runtime/apk-assets/bootstrap/arm64-v8a --cache-dir ../build-inputs/cache --native-dir ../build-inputs/jniLibs --android-metadata app/build/distribution/android-dependencies --output ../release-materials --apk-assets runtime/distribution-assets --python-source-directory ../python-sources --desktop-materials-directory ../desktop-materials
python -B -X utf8 tools/build_support/verify_distribution.py --directory ../release-materials --python-source-directory ../python-sources --desktop-materials-directory ../desktop-materials
```

## 输出

| 文件 | 内容 |
| --- | --- |
| `third-party-notices.zip` | 原始许可、公开依赖元数据、原创 LICENSE / NOTICE 与发行清单 |
| `available-sources.zip` | 原始上游源码、Termux 配方与可取得的 Maven 源 JAR |
| `manager-source.zip` | 管理器源码、构建脚本、锁文件及公共文档 |
| `release-inventory.json` | 实际依赖、资源摘要、来源及材料状态 |
| `collection.json` | 归档文件名、大小、摘要和条目数 |

ZIP 使用固定条目顺序与时间，并携带逐文件摘要。`--apk-assets` 只复制许可 ZIP 和索引，不把源码归档嵌入 APK。应用内可从“设置 → 关于 → 第三方许可”查看和导出许可原文。Shizuku SDK 的实际 Maven 依赖由 Gradle 收集，官方安装包与 Harness 的原始许可及来源锁一并收录；Harness 程序及专用 Node.js 在用户选择安装时下载。

源码收集仅包含公共说明；个人设备记录、调试日志、验收表和实施笔记不属于发布材料。

## 源码伴随包

Ubuntu 源码伴随包作为独立构建输入准备，按 dpkg 的准确源版本收集，并保留 Ubuntu 签名索引、原始文件名、源码包及 Debian 构建补丁。收集 APK 发行材料时会核对其与镜像中包版本和摘要的对应关系。

Python 源码由 `tools/build_support/collect_python_sources.py` 按固定计划收集，包括 PyPI sdist 和明确标识的上游源码补充。使用 `--python-source-directory` 将独立的 `python-source-packages.zip` 绑定至发行清单；它不进入 APK。

桌面离线包不属于原基础镜像的包清单，单独提供 `ubuntu-desktop-source-packages.zip`。当前锁定 163 个二进制包、117 个准确源码版本；从 Ubuntu 签名索引确认原始 `.dsc`、源码及 Debian 构建补丁文件，校验后保存为源码伴随包及 `ubuntu-desktop-source-collection.json`，其中 `desktopLockSha256` 必须对应当前桌面锁文件。准备材料时只读原始归档，不从用户手机收集。

1.4.1 同时将这些固定版本的桌面包预先配置为全新初始化资源，包的来源、版本及适用版权、源码材料不变。`manager-source.zip` 包含资源生成工具，`release.json` 的 `bundledDesktopSnapshot` 记录预安装归档的大小、摘要、基础镜像、依赖清单及构建配方关联；预安装归档本身随 APK 分发，不进入 Git。原始 `.deb` 仍随包保留，用于已有环境的离线修复。

在提供 `dpkg-deb` 的 Linux 或 WSL 环境中，从下载好的固定 `.deb` 提取原始版权文本并绑定该源码伴随包：

```bash
python3 -B tools/build_support/collect_desktop_materials.py --package-dir ../optional-assets/desktop-packages/arm64-v8a --source-dir ../desktop-source-inputs --runtime-dir ../build-inputs/runtime/apk-assets/bootstrap/arm64-v8a --output-dir ../desktop-materials
```

输出的 `desktop-materials.json`、`desktop-notices.zip`、源码包及源码记录一起保存在工程外。收集和验证发行材料时均传入 `--desktop-materials-directory`；正式构建器可在私有 `.local/build.json` 中设置 `desktopMaterialsDirectory`。版权文本进入 APK 许可查看器，桌面源码包作为独立 Release 附件，不进入 APK。缺少材料、源码版本或锁摘要不匹配时停止收集，不用旧基础镜像的源码记录替代新增包。

打包辅助工具的参数见相应 `--help`。完整源码伴随包应与其安装包一起提供，不能用根目录 MIT 或源码下载链接替代第三方许可要求。

`release-inventory.json` 中的 `openItems` / `releaseReady` 用于表示发行材料完整性。它们与应用功能无关；没有完成适用的授权、对应源码或构建映射时，保留实际状态。
