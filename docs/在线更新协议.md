# 在线更新协议

在线更新由用户在维护页主动检查。下载和包校验不停止服务，也不自动安装；下载完成后仍需查看安装说明并确认备份和更新。

## APK 信任配置

构建参数 `updateCatalogUrl`、`napcatCatalogUrl` 分别指定两个组件的签名目录 HTTPS 地址，`updatePublicKeyFile` 指定 ECDSA P-256 DER 公钥。公钥编入 APK，不从网络目录或更新包读取。私钥不进入项目源码或 APK。

正式构建使用编入 APK 的发布公钥，未配置时拒绝程序更新。没有更新地址的安装包会提示使用可信本地包或新版 APK，不宣称已是最新版。

```powershell
./gradlew.bat :app:assembleBundledRelease '-PbundledRuntime=true' '-PupdateCatalogUrl=https://YOUR_HOST/catalog.json' '-PupdatePublicKeyFile=C:/PRIVATE_RELEASE_PATH/update-public.der'
```

`YOUR_HOST` 替换为实际通道地址。安卓 APK 自身的签名按 Android 发布流程处理，配置说明见[更新与分发](更新与分发.md)。

## 签名目录

服务端返回一个 JSON 包装：

```json
{"payload":"BASE64_OF_EXACT_UTF8_BYTES","signature":"BASE64_OF_ECDSA_SIGNATURE"}
```

签名算法是 SHA256withECDSA，签名对象为 `payload` 解码后的原始字节。该字节内容示意如下：

```json
{
  "schema": 1,
  "channel": "stable",
  "sequence": 100,
  "issuedAtMs": 1792880000000,
  "expiresAtMs": 1793484800000,
  "entries": [{
    "id": "astrbot-4.29.3-arm64-example",
    "component": "astrbot",
    "version": "4.29.3",
    "abi": "arm64-v8a",
    "environmentKey": "64_HEXADECIMAL_CHARACTERS",
    "minAppCode": 1,
    "notes": "版本更新说明。",
    "url": "https://YOUR_HOST/astrbot-4.29.3.zip",
    "bytes": 12043301,
    "sha256": "64_HEXADECIMAL_CHARACTERS"
  }]
}
```

以上占位符不是可用目录。目录最多 100 个条目，包装不超过 256 KiB，解码后不超过 128 KiB。应用只对版本更高、运行环境摘要与架构匹配、最低应用版本满足的稳定更新提示升级；同版本仍可查看并重新下载。两个组件使用独立目录，不能交叉安装。没有合适条目时显示当前运行组合没有可用的新版本，不等同于所有上游组件都是最新版。

## 时效与旧目录拒绝

- 发布序号必须严格递增；同序号重取只允许完全相同的 payload 字节。
- 应用按目录地址与公钥身份在私有 manifests 目录保存最高序号和 payload 摘要。该记录不属于 persistent 快照，程序/数据回退不会回退目录序号。
- 发布者应在目录失效前重新发布。有效窗口最多 31 天；设备时间不处于有效窗口时拒绝目录。
- 下载开始及完成后都重新检查已缓存的签名目录和时效。
- 本地设备时间异常时提示检查时间或重新检查更新；应用不会忽略时效验证。

## HTTPS 与下载恢复

目录地址和所有资源地址必须为 HTTPS，无用户名密码或片段。保留系统证书和主机名验证；重定向逐跳检查且限制次数，拒绝降级到 HTTP。

下载进度保存在私有 `staging/online-download`。同一签名大小和 SHA-256 的残留文件可继续请求 `Range`；服务器返回 206 时严格检查 Content-Range，返回完整 200 时从头覆盖。不接受资源超过签名大小或不匹配的传输范围。断网时保留合法范围内的已下载进度，摘要错误则移除损坏文件。

下载完成先校验整个 ZIP 的 SHA-256 和大小，再由[签名维护包校验器](更新包格式与恢复协议.md)独立验证包签名、内部摘要、运行环境、归档路径、程序与 Dashboard。签名目录版本必须与包内版本相同。

仅在维护页再次确认后执行停机、完整快照、程序切换与程序/数据配套回退。AstrBot 检查真实启动及迁移；NapCat 先做 资源和运行依赖检查，仅在原本运行时重新启动并检查后台，原本停止的 QQ 保持停止。

## 生成待发布文件

发布者使用单独保管的 P-256 私钥签署程序包及目录，私钥不进入源码或 APK。发布工具必须验证程序包签名、压缩资源大小和摘要，拒绝重复的版本/环境/架构组合。先上传完整资源，再发布签名目录；每次目录内容变化都增加序号。

程序包绑定实际完整 ARM64 镜像的运行环境摘要，同时包含匹配的程序和 Dashboard。独立发行工具由维护者管理，不是构建 APK 的前置依赖。

## NapCat 官方程序包

NapCat 条目使用 `component=napcat`，另含 `qqVersion` 和 `backendSha256`。下载地址必须为 `https://github.com/NapNeko/NapCatQQ/releases/download/v版本/NapCat.Shell.zip`。发布工具核对上游附件 SHA-256，目录签名绑定整个原始 ZIP、后台程序摘要及已适配的 QQ/运行环境。App 不执行上游一键安装脚本，也不替换 QQ。

下载时执行完整目录时效验证。已下载包保留原始签名证明，每次安装重新校验签名、兼容性、大小、摘要和归档路径；与本地 AstrBot 维护包相同，已下载包可离线安装，不因目录后来过期而失去可安装性。版本标记绑定实际程序摘要，避免上游更换压缩变量名导致版本识别失效。

默认通道位于本项目 `updates` 分支的 `stable/astrbot.json`、`stable/napcat.json`、`stable/manager.json`；公钥保存在 `runtime/update-public-key.der`，默认编入 APK。分叉项目发布自己的包时，应使用自己的密钥和通道，不能复用本项目私钥。
