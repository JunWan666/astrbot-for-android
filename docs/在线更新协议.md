# 在线更新协议

组件在线更新由用户在维护页主动检查。AstrBot 默认使用官方 GitHub 最新稳定 Release，查看说明后点击“下载并更新”，连续执行下载、检查、备份和安装；检查和下载不停止服务，安装阶段才暂停服务及终端。管理器 APK 使用独立签名流程：检查后展示新版说明，用户点击“下载并安装”后自动下载、校验、创建安装前快照并进入系统安装器；未授予安装权限时引导授权，返回后继续，最终安装仍由系统确认。

## 官方 Release

默认 `updateCatalogUrl` 为 `https://api.github.com/repos/AstrBotDevs/AstrBot/releases/latest`。只在地址与对应官方入口完全相同时使用此协议；其他非空地址使用下文签名目录，空地址关闭对应入口。

始终拒绝 draft 和不支持的版本及附件命名。默认稳定通道同时拒绝 prerelease 标记及 Alpha、Beta、RC 版本后缀，即使上游误标正式版也不接受；用户主动选择预发布通道后，按版本顺序选择近期最新的稳定或预发布版本。AstrBot 将标签解析到具体提交，下载该提交源码 ZIP 和同版 `AstrBot-v版本-dashboard.zip`。附件大小与 SHA-256 来自官方 API；源码 ZIP 无上游附件摘要，通过官方 HTTPS 下载后记录本地摘要并在安装阶段再次检查，不宣称拥有本项目的签名证明。

下载仅接受 HTTPS，重定向逐跳限制为 `api.github.com`、`github.com`、`codeload.github.com`、`release-assets.githubusercontent.com`、`objects.githubusercontent.com`，保留系统证书验证。单个下载最多 256 MiB，解包限制文件数、总大小和路径，不执行安装器脚本。官方入口当前不保留断点续传文件，下载中断可重试；准备成功后仍可使用既有“安装已准备更新”入口。

AstrBot 同时检查代码与 Dashboard 版本及资源引用，使用当前 Python 环境检查新 requirements，不改动正在使用的 Python 包；已核对的迁移实现按源码识别，不以固定发布版本号判断。缺依赖或迁移方式未适配时停止，不替换现有程序。实际安装共用原有程序/数据事务与服务检查，失败回退。

本地 ZIP 导入独立于本节在线元数据协议：完全离线使用用户所选文件，不与官方内容比较，不补下载组件。可显式选择预发布版，不改变自动更新偏好，安装仍使用相同恢复事务。格式与本地检查见[更新包格式与恢复协议](更新包格式与恢复协议.md#本地-zip-离线导入)。

## 自定义签名目录

后续章节描述原有签名目录协议，供定制构建和旧客户端使用，不能将其签名和断点续传保证套用到官方 Release。

## APK 信任配置

构建参数 `updateCatalogUrl` 可覆盖为 AstrBot 的签名目录 HTTPS 地址，`updatePublicKeyFile` 指定 ECDSA P-256 DER 公钥。公钥编入 APK，不从网络目录或更新包读取。私钥不进入项目源码或 APK。

正式构建使用编入 APK 的发布公钥，未配置时拒绝程序更新。没有更新地址的安装包会提示使用可信本地包或新版 APK，不宣称已是最新版。

```powershell
./gradlew.bat :app:assembleBundledRelease '-PbundledRuntime=true' '-PupdateCatalogUrl=https://YOUR_HOST/catalog.json' '-PupdatePublicKeyFile=C:/PRIVATE_RELEASE_PATH/update-public.der'
```

`YOUR_HOST` 替换为实际通道地址。安卓 APK 自身的签名按 Android 发布流程处理，配置说明见[更新与分发](更新与分发.md)。

## 签名目录

服务端返回一个 JSON 包装：

```json
{"payload":"BASE64_OF_EXACT_UTF8_BYTES","signature":"BASE64_OF_ECDSA_SIGNATURE"}
```

签名算法是 SHA256withECDSA，签名对象为 `payload` 解码后的原始字节。该字节内容示意如下：

```json
{
  "schema": 1,
  "channel": "stable",
  "sequence": 100,
  "issuedAtMs": 1792880000000,
  "expiresAtMs": 1793484800000,
  "entries": [{
    "id": "astrbot-4.29.3-arm64-example",
    "component": "astrbot",
    "version": "4.29.3",
    "abi": "arm64-v8a",
    "environmentKey": "64_HEXADECIMAL_CHARACTERS",
    "minAppCode": 1,
    "notes": "版本更新说明。",
    "url": "https://YOUR_HOST/astrbot-4.29.3.zip",
    "bytes": 12043301,
    "sha256": "64_HEXADECIMAL_CHARACTERS"
  }]
}
```

以上占位符不是可用目录。目录最多 100 个条目，包装不超过 256 KiB，解码后不超过 128 KiB。应用只对版本更高、运行环境摘要与架构匹配、最低应用版本满足的稳定更新提示升级；同版本仍可查看并重新下载。目录组件必须为 AstrBot。没有合适条目时显示当前运行组合没有可用的新版本，不等同于所有上游组件都是最新版。

## 时效与旧目录拒绝

- 发布序号必须严格递增；同序号重取只允许完全相同的 payload 字节。
- 应用按目录地址与公钥身份在私有 manifests 目录保存最高序号和 payload 摘要。该记录不属于 persistent 快照，程序/数据回退不会回退目录序号。
- 发布者应在目录失效前重新发布。有效窗口最多 31 天；设备时间不处于有效窗口时拒绝目录。
- 下载开始及完成后都重新检查已缓存的签名目录和时效。
- 本地设备时间异常时提示检查时间或重新检查更新；应用不会忽略时效验证。

## HTTPS 与下载恢复

目录地址和所有资源地址必须为 HTTPS，无用户名密码或片段。保留系统证书和主机名验证；重定向逐跳检查且限制次数，拒绝降级到 HTTP。

下载进度保存在私有 `staging/online-download`。同一签名大小和 SHA-256 的残留文件可继续请求 `Range`；服务器返回 206 时严格检查 Content-Range，返回完整 200 时从头覆盖。不接受资源超过签名大小或不匹配的传输范围。断网时保留合法范围内的已下载进度，摘要错误则移除损坏文件。

下载完成先校验整个 ZIP 的 SHA-256 和大小，再由[签名维护包校验器](更新包格式与恢复协议.md)独立验证包签名、内部摘要、运行环境、归档路径、程序与 Dashboard。签名目录版本必须与包内版本相同。

用户在版本说明中选择“下载并更新”后，下载准备完成即进入停机、完整快照、程序切换与程序/数据配套回退；独立下载准备入口仍可用于分步维护。AstrBot 检查真实启动及迁移。

## 生成待发布文件

发布者使用单独保管的 P-256 私钥签署程序包及目录，私钥不进入源码或 APK。发布工具必须验证程序包签名、压缩资源大小和摘要，拒绝重复的版本/环境/架构组合。先上传完整资源，再发布签名目录；每次目录内容变化都增加序号。

程序包绑定实际完整 ARM64 镜像的运行环境摘要，同时包含匹配的程序和 Dashboard。独立发行工具由维护者管理，不是构建 APK 的前置依赖。
