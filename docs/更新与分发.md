# 更新与分发

## 更新通道

管理器 APK 使用 `JunWan666/astrbot-for-android` 的 GitHub 签名通道，目录在 `updates` 分支。AstrBot 默认直接查询其官方 GitHub 稳定 Release，不再等待本项目维护目录后才发现上游新版本。

| 对象 | 目录 | 行为 |
| --- | --- | --- |
| 管理器 APK | `stable/manager.json` | 验证包名、版本、签名和架构后交给系统安装器 |
| AstrBot 与 Dashboard | `AstrBotDevs/AstrBot` 官方最新稳定 Release | 固定标签对应的提交，下载源码与同版 Dashboard，检查依赖、备份、更新并验证启动 |
| Ubuntu / Python 与通用依赖 | 匹配 APK 内置环境 | 依赖变化时升级运行环境，可整套回退 |
| 独立 Linux QQ | 腾讯官网固定版本 | 在扩展组件中按需安装或更新，保留独立登录目录 |

目录地址为：

```text
https://raw.githubusercontent.com/JunWan666/astrbot-for-android/updates/stable/manager.json
https://api.github.com/repos/AstrBotDevs/AstrBot/releases/latest
```

组件和管理器分别发布。在组件页检查后查看版本说明，点击“下载并更新”连续执行下载、检查、备份和安装；没有新版时显示当前已是最新版本。官方入口只接受正式稳定 Release。下载阶段不停止服务，更新阶段暂停服务与终端，之后恢复原服务启停状态；终端命令不会自动重放。

稳定通道同时检查 `draft`、`prerelease` 和版本标签（`vX.Y.Z` 或 `X.Y.Z`）。若 `/releases/latest` 返回 alpha／beta 等标签，则从官方发布列表逐页查找近期稳定版本，最多检查 100 条记录；找不到时提示暂无支持的正式版，保留当前程序。

GitHub 发布附件使用 API 提供的大小和 SHA-256 校验；AstrBot 源码归档固定到标签解析出的提交，通过官方 HTTPS 获取，并记录下载摘要供准备及安装阶段重复检查。源码归档没有本项目发布者签名，不能与签名维护包混为一谈。HTTPS 重定向逐跳限制在 GitHub 官方主机；不会执行上游安装脚本。

新版 AstrBot 必须满足现有 Python 依赖，且其迁移实现能被当前观察器识别；未满足时在替换前停止，保留现有程序，不自动升级 Python 包。使用相同已核对迁移源码的新版不再受固定版本号限制。上游新版与已有平台适配器、插件或原生依赖的兼容性不能仅凭 Release 判断。安装后使用现有服务与数据库检查，失败时恢复旧程序和数据。

完整 APK 在 [Releases](https://github.com/JunWan666/astrbot-for-android/releases/latest) 下载。管理器正式版使用 `vMAJOR.MINOR.PATCH` 标签并设为最新发布；独立组件包单独发布，不设为最新发布，保留已有下载地址，确保默认下载入口始终指向 App。

Release 标题统一为 `v版本号 · AstrBot for Android`。安装包体积显著变化时，在 Release 的“下载安装”和签名更新目录的版本说明中明确写出大小、相对上一正式版的变化及原因。1.4.1 完整 APK 约 1022 MiB（1 GiB），比 1.4.0 增加约 175 MiB，用于携带加快全新初始化的预配置桌面资源；原始离线包仍供已有环境修复使用。发布目录中的 `bytes` 和 SHA-256 必须取自最终 APK，不使用说明中的约数。

1.5.0 完整 APK 约 729 MiB，比 1.4.1 减少约 293 MiB，原因是移除内置非官方消息组件及配套 QQ 客户端；通用 Ubuntu 与预配置桌面资源仍随包提供，独立 Linux QQ 按需下载。

## 签名与构建参数

Android keystore 签署 APK，决定是否允许覆盖安装。ECDSA P-256 密钥签署更新目录和 AstrBot 程序包。两类私钥分别保管，均不进入仓库或 APK。

| 参数 | 默认值或作用 |
| --- | --- |
| `managerCatalogUrl` | 上述管理器目录 |
| `updateCatalogUrl` | 上述 AstrBot 官方 Release API；改为其他 HTTPS 地址时使用原有签名目录协议 |
| `updatePublicKeyFile` | `runtime/update-public-key.der` |
| `appVersionName` / `appVersionCode` | 显示版本与递增的 Android 版本号 |

分叉项目应更换自己的公钥和通道。将通道参数显式设为空可关闭对应在线入口；应用会说明未配置，不将缺少通道当作最新版。

## 管理器 APK

在 App 的“设置 → 关于 → 检查更新”中主动检查。发现适用新版后显示版本说明，点击“下载并安装”即连续完成下载、校验、安装前快照和打开系统安装器；缺少安装权限时引导授权，返回后继续。取消下载保留续传进度，已下载新版可在再次检查后继续安装；没有适用新版时明确提示已是最新版本。

新版说明中也可选择“使用外部浏览器下载”，打开同一已验证更新目录中的 APK 地址。外部下载的文件由浏览器和系统安装器处理，不经过 App 内的自动校验及安装前快照；需要这些步骤时使用内置“下载并安装”。

构建完整 Release 后，用长期 Android keystore 签名，再生成管理器目录：

使用已完成正式签名和校验的 APK，目录条目绑定包名、版本、架构、证书指纹、文件大小及 SHA-256。签署目录后再开放安装入口。

生成器读取 APK 的真实身份、签名、架构和摘要，只接受完整运行资源包。覆盖安装要求包名、签名集合相同且 versionCode 更高。尚未发布管理器新版时，目录可保留空条目，App 会提示没有适用的新版本。

## 发布与续期

1. 固定版本、来源和兼容组合，准备适用的许可及源码材料。
2. 先上传不可变 Release 资源。
3. 生成更高 `sequence` 的签名目录，提交到 `updates` 分支的 `stable/`。
4. 不改写已公开的附件；撤回版本也通过更高目录序号发布。

目录有效期最多 31 天，默认每次签署 30 天。`Renew update catalogs` 工作流每周续期，也可手动运行；只重新签署既有条目，不自动引入未经适配的上游新版本。仓库 Actions Secret `UPDATE_SIGNING_KEY` 保存独立的更新目录私钥。应保留工程外离线副本，续期工作流需位于默认分支；发布主分支后同样保留此工作流。工作流先检出 `updates` 分支，再使用该分支自带的发行工具；主分支不需要保存这些工具。

协议与恢复细节见[在线更新协议](在线更新协议.md)、[更新包格式与恢复协议](更新包格式与恢复协议.md)，第三方材料要求见[发行材料](发行材料.md)。
