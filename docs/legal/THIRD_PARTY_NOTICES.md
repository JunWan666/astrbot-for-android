The native ClawBot authorization page generates QR codes locally with [ZXing core 3.5.3](https://github.com/zxing/zxing/tree/zxing-3.5.3), under Apache-2.0. Its resolved artifact, digest and available source and license material are included by the release dependency collector. Authorization itself uses the installed AstrBot adapter APIs.

The optional permissions screen uses the official [Shizuku API and provider 13.1.5](https://github.com/RikkaApps/Shizuku-API), under MIT, copyright (c) 2021 RikkaW. The original license and its source digest are retained in `runtime/shizuku-api-LICENSE.txt` and `runtime/shizuku-api.lock.json`, and included in the APK notice collection. Resolved Maven artifacts, hashes and available sources are recorded by the release dependency collector. The APK also carries the unmodified official [Shizuku 13.6.0.r1086.2650830c installer](https://github.com/RikkaApps/Shizuku/releases/tag/v13.6.0), under Apache-2.0. Its source URL, size, SHA-256 and original signing certificate are pinned in `runtime/shizuku-manager.lock.json`; its original license accompanies the installer and is included in the notice collection. The user explicitly installs it through the Android installer and starts and authorizes Shizuku separately.

The optional [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) extension downloads official npm package `@deepseek-ai/dsh` version `0.2.1-rc.2`, under MIT, only on request. Its original license is retained in `runtime/deepseek-harness-LICENSE.txt`. A private Node.js `24.22.2` ARM64 runtime is downloaded from nodejs.org with a pinned SHA-256; Node.js and dependencies retain their upstream license notices. Version and source metadata are recorded in `runtime/deepseek-harness.lock.json`; the complete npm dependency lock (including individual license metadata and archive integrity values) is in `app/src/main/assets/runtime/harness/package-lock.json`. Neither Node.js nor Harness executables or dependencies are embedded in the default APK. The app starts the unmodified Web UI on loopback by default, with optional LAN binding and upstream authentication, without prefilled model credentials.

The cpolar extension downloads the official Linux ARM64 client 3.3.12 only when requested. Its ZIP and executable hashes are pinned in `CpolarRepository.kt`. No cpolar executable is bundled in this repository, its source distribution, or the default APK. The client remains subject to [cpolar's terms and account plan](https://www.cpolar.com/); the manager's MIT license does not apply to it.

The original Android manager code and documentation are copyright (c) 2026 JunWan666 and licensed under the [MIT License](../../LICENSE). Attribution is recorded in [NOTICE](NOTICE).

The offline Ubuntu terminal renderer bundles unmodified [xterm.js 5.5.0 and addon-fit 0.10.0](https://github.com/xtermjs/xterm.js), both under MIT. `runtime/sources.lock.json`, `runtime/projects.lock.json` and `runtime/distribution-sources.lock.json` pin downloads. The prepared native resources use the following transformations: PRoot programs are packaged with `.so` filenames, and the `libtalloc.so.2` ELF dynamic string becomes `libtalloc.so` without changing string offsets. The Android NDK builds the manager's process owner and SSH PTY bridge from `native/process_runner.c` and `native/terminal_runner.c`; their per-ABI output hashes are recorded in the release inventory. The SSH server uses the Gradle-pinned Apache MINA SSHD libraries, not the Dropbear packages considered during investigation.

Run `:app:collectReleaseDependencyMetadata`, then `python tools/build_support/collect_distribution.py --apk-assets runtime/distribution-assets`. The collector reads only pinned build inputs and allowlisted source files; it never reads device data. It creates:

- `third-party-notices.zip`: original notice texts, public package metadata and a partial release inventory. Bundled APKs include this archive, with an application viewer and export action.
- `available-sources.zip`: original AstrBot/native source archives, Termux packaging recipes and resolved Maven source JARs. This is **not complete corresponding source**.
- `manager-source.zip`: manager code, build/provisioning scripts, automated checks, locks and public documentation; excludes device data, caches, binary runtimes, signing material and build outputs.
- `ubuntu-source-packages.zip`: 262 exact Ubuntu source packages (833 original files), Debian build/patch archives and signed index evidence. Prepared as a separate build input; separate from the APK and `available-sources.zip`.
- `python-source-packages.zip`: a separate companion with 148 exact PyPI sdists and 2 explicitly identified upstream tag/commit archives, original metadata and fixed source lock. Bind its external directory using `--python-source-directory` when collecting and verifying release materials; it is not embedded in the APK or copied into the main output directory.
- `release-inventory.json` and `collection.json`: exact versions, SHA-256, file manifests, scope and unresolved delivery items. They contain no host cache paths.

Python source archives are collected for all 150 pinned versions; complete corresponding source, wheel provenance, vendored/native/JavaScript dependency mapping, binary build provenance and applicable third-party grants require separate release review. The original manager is MIT licensed. Ubuntu source archives are collected; matching binary rebuilds have not been performed. Merely retaining URLs or source JARs does not complete those obligations. Rebuild the inventory for every runtime/dependency change. Collection, source companions and required release materials are described in the [distribution guide](../发行材料.md).

The full APK now bundles 163 pinned Ubuntu 24.04 ARM64 desktop binary packages (117 exact source-name-and-version pairs), prepared offline at initialization. Their original URLs, versions, lengths, SHA-256 values and source-package identities are in `runtime/desktop-packages.lock.json`, bound to the base runtime hash. Xvfb (X.Org), Fluxbox, x11vnc, noVNC, websockify, xauth, tmux, D-Bus, fonts, GCC/G++, make, Python and curl retain their individual licenses. The original `.deb` files retain their copyright texts; these texts are also collected into the APK notice archive, separately from the base-image inventory. `ubuntu-desktop-source-packages.zip` is a separate release companion containing 117 exact source packages, Debian build/patch files and authenticated Ubuntu source-index evidence. It does not enter the APK. Source collection is not a binary rebuild or blanket redistribution approval.

`tools/build_support/collect_desktop_materials.py` reads pinned `.deb` payloads using `dpkg-deb` without installing or executing package contents. It verifies binary hashes, retains original copyright texts, and binds the separate exact-source archive to the desktop lock. Run it in Linux or WSL, then pass `--desktop-materials-directory` to the distribution collector and verifier. The release builder accepts `desktopMaterialsDirectory` in its private build configuration and refuses to silently omit these materials.

The separate original Tencent Linux QQ 3.2.34-53644 is still downloaded directly from Tencent only on request; its official URL, size and SHA-256 are pinned in `app/src/main/assets/runtime/desktop/sources.json`. This separate QQ archive is not embedded in the default APK. It is proprietary and is not covered by the manager MIT license. The guest compatibility helper sources are original manager code under MIT and are compiled locally in the Ubuntu guest during desktop preparation; user-supplied external libraries retain their own terms.
