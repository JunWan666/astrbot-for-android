# 更新包格式与恢复协议

更新包支持本机导入，也可通过 HTTPS 签名目录获取、断点下载、校验后确认安装。在线协议见[在线更新协议](在线更新协议.md)。

## 信任与兼容性

- ZIP 必须且只能包含 `manifest.json`、`manifest.sig`、`program.tar.bin`，拒绝重复项。
- 签名为 ECDSA P-256 / SHA-256，对 `manifest.json` 的原始 UTF-8 字节签名；应用使用 APK 内置的 DER 公钥，包内提供的公钥不参与信任判断。
- 正式构建通过 `updatePublicKeyFile` 内置 P-256 公钥，发布者使用对应的外部私钥签署程序包。未配置密钥时拒绝独立程序更新，不能跳过签名校验。
- 签名清单包含版本、最低 App 版本、架构、运行环境摘要、压缩资源大小及 SHA-256、解包大小、文件数、来源记录、通道和版本说明。
- 运行环境摘要绑定基础镜像、Linux QQ package、Python 配置和完整依赖锁。AstrBot 与 NapCat 程序版本独立变化；运行环境和原生依赖变化须使用匹配 APK，不能任意替换安卓可执行文件。
- 校验程序版本与匹配 Dashboard 版本，核对入口引用的 JS/CSS 文件。Dashboard 版本的 `v` 前缀按上游规则归一化。
- 归档只接受目录与普通文件，拒绝符号链接、硬链接、特殊文件、越界和重复路径；解包限制资源大小与文件数。

程序包应从 `runtime/maintenance-candidates.lock.json` 锁定的源码与 Dashboard 生成程序包，支持 4.29.1 与 4.29.3。SHA-256 不匹配时拒绝生成；发布时使用独立签名目录声明下载地址和版本。

## 更新事务

1. 文件选择器导入，先复制到私有暂存目录，校验签名、摘要、兼容性、解包文件与空间，展示版本说明。
2. 用户确认后重新校验暂存包，确保待安装内容仍对应签名。
3. 维护互斥中停止两个服务，创建完整 persistent 一致性快照，记录实际旧版本组合。
4. 先持久化 `operations/update.json` 的 `prepared` 阶段，再把当前程序移动到带 UUID 的保留目录，把已校验程序切换至 `/opt/astrbot`，记录 `switched`。
5. 检查 SQLite、程序入口、实际迁移结果和真实后台；启动后再次检查 SQLite。即使更新前 AstrBot 未运行，也实际启动一次验证后恢复原运行偏好。后台关闭时仍要求进程保持运行且迁移检查通过。
6. 恢复原先运行服务后记录 `committed`，保存旧程序与其对应快照到回退索引。保留最近一对程序回退资源；被索引引用的数据快照不允许从管理页删除。

QQ 登录与模型连接由各自的配置和网络决定，管理器分别显示服务状态与业务连接状态。

在线更新在导入之前增加签名目录、时效、序号、HTTPS 和完整 ZIP 摘要校验。检查和下载期间不停止服务，不自动安装；准备成功后仍进入同一确认界面与维护事务。

固定 AstrBot 4.29.1/4.29.3 的迁移帮助函数会捕获部分异常并继续启动。管理器通过应用内置启动观察脚本，包装原迁移调用并观察迁移模块自身的结构化错误调用；保留原返回值、异常和日志转发，不从 stdout 文本推断迁移成功。观察记录在用户数据之外的 `/manager/astrbot-startup.json`，绑定当前启动 nonce。任何迁移错误都使本次更新回退；无法识别的版本不通过更新迁移检查，但仍保留程序运行和诊断入口。

## 回退与中断恢复

手动回退先复制保留的旧程序并校验，另存当前数据快照后，再切换到旧程序并恢复它对应的数据。恢复点后的数据不会合并；回退操作自身也保留当前程序及对应数据，以便再次回退。

未提交更新恢复时：先回退未完成的数据恢复日志，再恢复旧程序并核对组合摘要，然后从更新前快照恢复数据并检查数据库。完成后才移除更新日志。恢复日志和更新日志按固定顺序处理，可在恢复再次中断后重试；错误时保留文件与日志。

管理页重新打开且没有现有控制器时会自动触发未完成维护操作恢复，并按持久化运行意图重新启动对应服务，重新探测真实接口。运行服务支持空命令重建并核对偏好，主动停止会先持久化停止意图；系统或厂商终止应用后，可重新打开 App 恢复；应用无法覆盖系统的强行停止策略。

## NapCat 独立事务

NapCat 使用上游原始 Shell ZIP，信任证明来自签名目录，详情见[在线更新协议](在线更新协议.md)。暂存、事务日志与回退目录均与 AstrBot 分开。只替换 `opt/qq/resources/app/app_launcher/napcat`，不改 Linux QQ；`persistent` 下的配置、插件与 QQ 会话保留，旧式程序目录下的自定义插件也会迁移，发生同名冲突时中止并保留原目录。

安装前暂停两个服务并创建一致性快照；检查资源、运行依赖和数据库，再恢复原本运行的服务。QQ 原本停止时仅静态检查，保持停止，后台可用性在下次启动时检查。原本运行时要求后台重新就绪，否则回退。中断恢复顺序为整套环境、AstrBot、NapCat、数据恢复；每个已提交的组件更新保留自己的程序与配套数据恢复点。

程序与快照必须成套恢复。如果回退点创建后另一个组件已变更，拒绝拼接旧组合，提示使用匹配的整套环境和备份。
