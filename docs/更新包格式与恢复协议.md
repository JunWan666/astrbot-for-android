# 更新包格式与恢复协议

本节描述自定义签名维护包及通用恢复事务，支持本机导入或从自定义 HTTPS 签名目录下载。默认官方 Release 的文件格式和信任来源不同，使用相同的安装恢复事务，在线协议见[在线更新协议](在线更新协议.md)。

## 本地 ZIP 离线导入

文件选择器同时选择同版源码 ZIP 与 Dashboard ZIP，或单选已包含主程序与同版网页的完整 ZIP。应用从 `astrbot/__init__.py` 与 `dist/assets/version` 识别版本，接受有单层顶级目录及无顶级目录的源码包；外部同版 Dashboard 可覆盖源码包里旧的内嵌网页。仅有网页或缺少同版网页时提示补选文件。此流程完全离线，不查询官方 Release、不比较官方内容，不自动下载缺失文件，也不因本地内容经过修改而拒绝。

本地暂存记录使用 `origin=local-import`，与线上 `origin=github` 记录区分；不会生成已验证官方来源的声明。SHA-256 只绑定用户选定的本地暂存字节，安装确认前复查文件未变化，不作为官方真实性证明。支持稳定版本及显式选择的 Alpha、Beta、RC，导入不修改自动检查通道。仍检查现有 Python 依赖、迁移实现、前后端版本、资源完整性与归档路径，再交由下述恢复事务安装。签名维护包单独识别；出现签名包字段时只能通过签名验证，不回退到无签名 ZIP 路径。

## 信任与兼容性

- ZIP 必须且只能包含 `manifest.json`、`manifest.sig`、`program.tar.bin`，拒绝重复项。
- 签名为 ECDSA P-256 / SHA-256，对 `manifest.json` 的原始 UTF-8 字节签名；应用使用 APK 内置的 DER 公钥，包内提供的公钥不参与信任判断。
- 正式构建通过 `updatePublicKeyFile` 内置 P-256 公钥，发布者使用对应的外部私钥签署程序包。未配置密钥时拒绝独立程序更新，不能跳过签名校验。
- 签名清单包含版本、最低 App 版本、架构、运行环境摘要、压缩资源大小及 SHA-256、解包大小、文件数、来源记录、通道和版本说明。
- 运行环境摘要绑定基础镜像、Python 配置和完整依赖锁。AstrBot 程序版本独立变化；运行环境和原生依赖变化须使用匹配 APK，不能任意替换安卓可执行文件。
- 签名清单可选 `compatibleEnvironmentKeys`，列出经发布者核对的 1–8 个完整环境摘要，必须包含主 `environmentKey`，不接受重复或通配值。旧清单仍只匹配主摘要；旧客户端不会识别新增兼容列表。
- 校验程序版本与匹配 Dashboard 版本，核对入口引用的 JS/CSS 文件。Dashboard 版本的 `v` 前缀按上游规则归一化。
- 归档只接受目录与普通文件，拒绝符号链接、硬链接、特殊文件、越界和重复路径；解包限制资源大小与文件数。

程序包应从 `runtime/maintenance-candidates.lock.json` 锁定的源码与 Dashboard 生成。锁文件区分已验证组合与待实机验证候选，不代表其中每个版本已公开发布。SHA-256 不匹配时拒绝生成；发布时使用独立签名目录声明下载地址和版本。4.30.0-alpha.1、4.30.0-beta.1 维护包的最低管理器版本代码为 `10052`，不能供未适配新迁移实现的 1.5.0 直接安装。

## 更新事务

1. 文件选择器导入，先复制到私有暂存目录，校验签名、摘要、兼容性、解包文件与空间，展示版本说明。
2. 用户确认后重新校验暂存包，确保待安装内容仍对应签名。
3. 维护互斥中停止 AstrBot，创建完整 persistent 一致性快照，记录实际旧版本组合。
4. 先持久化 `operations/update.json` 的 `prepared` 阶段，再把当前程序移动到带 UUID 的保留目录，把已校验程序切换至 `/opt/astrbot`，记录 `switched`。
5. 检查 SQLite、程序入口、实际迁移结果和真实后台；启动后再次检查 SQLite。即使更新前 AstrBot 未运行，也实际启动一次验证后恢复原运行偏好。后台关闭时仍要求进程保持运行且迁移检查通过。
6. 恢复原先运行服务后记录 `committed`，保存旧程序与其对应快照到回退索引。保留最近一对程序回退资源；被索引引用的数据快照不允许从管理页删除。

QQ 登录与模型连接由各自的配置和网络决定，管理器分别显示服务状态与业务连接状态。

签名通道在导入之前增加目录签名、时效、序号、HTTPS 和完整 ZIP 摘要校验。用户在说明页点击“下载并更新”后连续下载、检查并进入维护事务，检查和下载期间不停止服务。

已核对的 AstrBot 迁移帮助函数会捕获部分异常并继续启动。管理器按帮助模块源码摘要识别实现，覆盖官方 4.29.1、4.29.3/4.29.4、4.30.0-alpha.1/beta.1 及使用相同实现的后续版本；包装原迁移调用并观察模块自身的结构化错误调用，保留原返回值、异常和日志转发，不从 stdout 文本推断成功。新版本向外传播的迁移异常同样记录为失败。观察记录在用户数据之外的 `/manager/astrbot-startup.json`，绑定当前启动 nonce。任何迁移错误都使本次更新回退；无法识别的迁移实现不通过更新检查，官方包在替换前即拒绝，但仍保留原程序运行和诊断入口。

## 回退与中断恢复

手动回退先复制保留的旧程序并校验，另存当前数据快照后，再切换到旧程序并恢复它对应的数据。恢复点后的数据不会合并；回退操作自身也保留当前程序及对应数据，以便再次回退。

未提交更新恢复时：先回退未完成的数据恢复日志，再恢复旧程序并核对组合摘要，然后从更新前快照恢复数据并检查数据库。完成后才移除更新日志。恢复日志和更新日志按固定顺序处理，可在恢复再次中断后重试；错误时保留文件与日志。

管理页重新打开且没有现有控制器时会自动触发未完成维护操作恢复，并按持久化运行意图重新启动对应服务，重新探测真实接口。运行服务支持空命令重建并核对偏好，主动停止会先持久化停止意图；系统或厂商终止应用后，可重新打开 App 恢复；应用无法覆盖系统的强行停止策略。
